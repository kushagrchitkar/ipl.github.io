The data layer is precomputed and file-based. There is no runtime API, local database, or build script that regenerates derived files. `main.js` treats loaded datasets by array position, so the order in its `promises` array is part of the contract [@main]. See [[dashboard-runtime]] for the load path.

## Match-Level Data

`data/matches_cleaned3.csv` is the central match table. It has 950 rows for IPL seasons 2008 through 2022 and includes `ID`, `City`, `Date`, `Season`, teams, venue, toss winner/decision, winning team, match margin, player lists, umpires, and `Venue_cleaned` [@matches]. The current code uses it for:

- Team win totals and selected-team opponent records in [[team-success-views]].
- Umpire node and pair counts in [[umpire-network]].
- Joining ball-by-ball rows to match dates for batsman year-series charts in [[batsman-performance-flow]].
- City-level toss decision and toss-winner outcome counts in [[humidity-toss-flow]].

`cleanData()` converts match `ID`, `Date`, `Season`, and `Margin`, but leaves `TossDecision`, `WinningTeam`, `Umpire1`, `Umpire2`, `City`, and team names as strings [@main]. Any new visualization that relies on these string fields inherits the dataset’s exact naming, including legacy names such as `Bangalore` versus `Bengaluru`.

## Ball-By-Ball Data

`data/IPL_Ball_by_Ball_2008_2022_cleaned.csv` has 225,954 rows and includes ball identity, innings, over/ball number, batter, bowler, non-striker, run values, wicket flags, dismissal fields, and batting team [@balls]. `main.js` converts numeric identifiers and run/wicket fields before the data reaches visualizations [@main].

The ball dataset is not used directly by the batsman ranking bars in the current runtime. `BarVis.organizeDataInitial()` contains the old derivation logic that grouped ball rows by `batter`, calculated totals, and copied JSON output from the console, but the live chart consumes `data/batsmanData.json` instead [@batsman] [@main]. The line chart still joins ball rows to `matches_cleaned3.csv` by `ID` so it can aggregate the selected batsman by match year [@main].

## Precomputed Batsman Data

`data/batsmanData.json` has 136 player rows with `name`, `sumBatsmanRuns`, `numPlayerOuts`, `average`, and `strikeRate` [@batsman]. It is the source of truth for the ranking bar chart. The code comment in `BarVis.organizeDataInitial()` says the JSON was generated by logging the derived structure and copying it into the file, so future regeneration is manual unless a script is added [@batsman].

One important metric difference exists: the precomputed `strikeRate` is `sumBatsmanRuns / totalOccurrences`, while the line chart’s yearly strike-rate calculation multiplies that ratio by 100 [@batsman]. Agents changing labels or comparisons should decide whether the project means cricket strike rate per 100 balls or a raw run-per-ball ratio.

## Points Table

`data/pointstable.csv` has 136 rows for seasons 2008 through 2023 and includes `Year`, `Rank`, `Team`, win/loss/no-result counts, net run rate, runs for/against, and points [@points]. It is the only local dataset that extends to 2023. The match and ball datasets stop at 2022 [@matches] [@balls].

The slope graph coerces `Year` and `Rank` inside `SlopegraphVis`, groups rows by `Team`, and labels only teams present in the last available year [@points]. Team-name spellings matter because colors are hard-coded against literal strings in visualization classes.

## Humidity Data

`data/matches_humidity.json` has 950 rows and combines every match row with `humidity`, `latitude`, `longitude`, and `elevation` [@humidity]. `MapVis.mergeData()` documents how the file was originally created from per-city weather CSVs in `data/IndiaWeather/`, but those source weather files are not present in the current repo. The method also states the merge took around ten minutes and was not suitable for live `wrangleData()` execution [@map].

At runtime, the map groups the prejoined humidity rows by `City`, averages numeric humidity values, and renders city dots except for `Sharjah`, `Dubai`, and `Abu Dhabi` [@map]. The coin-toss bars do not use humidity directly for counts; humidity only determines the clicked city color passed to the bar charts [@map].
