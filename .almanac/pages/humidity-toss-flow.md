The humidity/toss flow asks whether city humidity relates to coin-toss decisions and whether the toss winner converts those decisions into match wins. The page section pairs a D3 map of India with two bar charts: one for toss decision counts and one for matches won by toss winners, grouped by toss decision [@index].

## Map Data And Rendering

`MapVis` receives remote India state GeoJSON, `matches_cleaned3.csv`, and `matches_humidity.json` [@main]. The humidity JSON is already joined to match rows and adds `humidity`, `latitude`, `longitude`, and `elevation` [@humidity]. `MapVis.wrangleData()` groups this file by `City`, averages numeric humidity values, and keeps the first row’s coordinates for the rendered dot [@map].

The base map colors every Indian state as if it had 50% humidity, then overlays city dots colored by average humidity from a blue linear scale over `[0, 100]` [@map]. The map intentionally filters out `Sharjah`, `Dubai`, and `Abu Dhabi` before drawing dots, because the base geography is India-only [@map]. Tooltip text shows the city and overall average humidity [@map].

`MapVis.mergeData()` is historical project memory embedded in code. It shows that the current humidity file was originally generated by flattening per-city weather CSVs, matching rows by city and date, adding coordinates/elevation, and copying logged JSON output into the data folder [@map]. The referenced `data/IndiaWeather/` folder is not present in the current repository, so regenerating `matches_humidity.json` requires recovering or recreating those weather inputs.

## Toss Bar Charts

`CoinTossBarGraph` is a small reusable D3 bar chart configured by `isDecision` [@toss]. When `isDecision` is true, its title and x-axis represent `Coin Toss Decision`; otherwise they represent `Winner based on Coin Toss Decision` [@toss]. Both charts render `decision` categories on a band scale and `count` on a linear y-scale [@toss].

The map owns the data wrangling for both bars. For a clicked city:

- `coinTossDecision(city, color)` filters `matchData` by `City`, counts each `TossDecision`, and sends `{ decision, count }` rows to the decision bar chart [@map].
- `coinTossWinner(city, color)` filters matches by city, counts rows where `TossWinner === WinningTeam`, groups those successful toss-winner outcomes by `TossDecision`, sorts by decision, and sends rows to the winner bar chart [@map].

The bar color is the clicked city’s humidity color, so the count charts visually inherit map humidity even though their y-values are toss counts [@map] [@toss].

## Default State And Dependencies

`MapVis` initializes the two bar charts to `Chennai` before drawing the map, using `colorBasedOnHumidity("88")` as the starting color [@map]. This depends on global `indiaMapCoinTossDecision` and `indiaMapCoinTossWinner` already being constructed by `main.js` [@main] [@map].

The remote India GeoJSON is loaded in the same `Promise.all` as all local datasets [@main]. If that remote request fails, none of the visualizations initialize, even though only the map needs the GeoJSON. Isolating the map load would make non-map sections more resilient.
